# Кварта — лендинг обжарки кофе

Тестовое задание: лендинг с формой заявки для обжарки «Кварта» (Минск).
Next.js 16 (App Router), TypeScript strict, CSS Modules, zod, SQLite/Turso.

- Сайт: _ссылка после деплоя_
- Lighthouse (мобильная версия): _скриншот после деплоя_

```bash
pnpm install
pnpm dev          # http://localhost:3000, база создаётся в ./data/leads.db
pnpm check:api    # проверка POST /api/lead, в том числе одновременных отправок
```

## Куда идут заявки и почему

SQLite: одна таблица и транзакции, отдельный сервер не нужен. Файловая система Vercel
не постоянна, поэтому в продакшене та же SQLite хранится в Turso (libSQL), а локально лежит
в файле. Драйвер и SQL в обоих случаях одни и те же. Повтор того же номера за 10 минут
отсекает один атомарный `INSERT … WHERE NOT EXISTS`, так что двойной тап не создаёт вторую заявку.
Источник клиента сохраняется вместе с заявкой: UTM, страница входа, referrer. Копия заявки уходит в Telegram.

## Где ИИ ошибся

- Первую версию собрал из типовых секций лендинга. Выглядела сгенерированной, поэтому переделали по своему дизайну.
- На десктопе карточки сортов растягивались на всю высоту экрана. Заметил при просмотре и попросил ограничить.
- На телефоне предвыбранный вариант «Подписка» оставался за краем ряда чипов. Заметил при проверке с телефона.
- `prompt.xml` требовал PostgreSQL, хотя бриф оставляет выбор хранилища открытым. ИИ сам указал на это расхождение,
  остановились на SQLite + Turso. Ещё ИИ использовал устаревшую в Next 16 опцию `preferredRegion`, это выдала сборка.

## Допущения и что не успел

- В брифе нет телефона и соцсетей, поэтому при ошибке отправки предлагаем прийти в мастерскую (адрес и часы работы).
- Идентификаторы рекламы `yclid` и `fbclid` уже собираются на клиенте, но колонок под них в базе ещё нет.
- Нет просмотра заявок для менеджера, кроме Telegram и консоли Turso. Не было в задаче, со временем стоит добавить.
